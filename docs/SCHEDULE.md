# CalDesk 实施排期与确认清单

> 由 [REQUIREMENTS.md](./REQUIREMENTS.md) 与 [ROADMAP.md](./ROADMAP.md) 派生。
> 本文回答三件事：**① 排期与工时估计 ② 阶段划分与依赖 ③ 需要你提前确认/拍板的事项**。
> 工时为「人日（d）」估算，指专注单人开发；可借 Linux/Windows 双轨道压缩墙钟时间。

---

## 一、总览

- **总工时估计**：约 **20–24 人日**（≈ 4–5 周专注开发），含联调与手测。
- **关键路径**：`M0 → M1 → M2 → M3 → M4 → M5 → M7`，`M6`（重复+提醒）可在 M5 期部分并行。
- **双轨道**：
  - **Linux 轨**（本机，持续可推进 + 可对 radical 跑集成测试）：`CalDav` / `Storage` / `Core` 逻辑、`Recurrence`、同步引擎、单测。
  - **Windows 轨**（你的 Windows 机，集中突击）：WPF `App`（视图/窗口/托盘/开机启动/发布）。
- **节奏建议**：阶段 A、B 的**业务逻辑 90% 可在 Linux 完成并通过自动化测试**，Windows 仅在每阶段末做 UI 集成突击。这能把「必须切到 Windows」的次数降到 3–4 次。

---

## 二、三个宏阶段

### 阶段 A —— 连通与地基（M0 + M1）
> 目标：能从 radical 读出真实事件并落库。

- 覆盖：解决方案骨架 + CalDAV 发现/查询 + 时区处理 + 落库。
- **门槛（Definition of Done）**：本机对 `work`/`personal`/`holiday` 三日历跑通 `calendar-query`，事件（含浮动时间）正确入库，ETag/`remote_href` 完整。
- 工时：**M0 1d + M1 3d ≈ 4d**

### 阶段 B —— 可用客户端（M2 + M3 + M4）
> 目标：能看、能加改删、能双向同步。

- 覆盖：SQLite 缓存 + 周视图 + 快速新增 + PUT/DELETE + `If-Match` + 同步引擎 + 冲突处理。
- **门槛**：一个可日常使用、断网可用、联网自动补传、冲突不丢数据的读写客户端。
- 工时：**M2 3d + M3 3d + M4 3d ≈ 9d**

### 阶段 C —— 桌面体验与发布（M5 + M6 + M7）
> 目标：成为常驻桌面的小工具，处理重复，单文件 EXE 发布。

- 覆盖：无边框透明窗口（三模式）+ 托盘 + 开机启动 + 多显示器 + 重复事件 + 提醒 + 单文件发布。
- **门槛**：重启后自动常驻、透明/锁定/置顶可用、重复事件正确、单 EXE 干净运行。
- 工时：**M5 4d + M6 3d + M7 2d ≈ 9d**

## 三、里程碑排期表

| 里程碑 | 主题 | 工时 | 依赖 | 主轨道 | 关键产出 / 验收门槛 |
|---|---|---|---|---|---|
| **M0** | 工程地基 | 1d | — | 双 | 五项目骨架；`dotnet build`/`test` 绿；分层依赖正确 |
| **M1** | CalDAV 连通 | 3d | M0 | Linux | 发现 + 完整URL兜底 + `calendar-query` + 时区；对 radical 三日历跑通自检 |
| **M2** | 缓存 + 周视图（只读） | 3d | M1 | Linux(逻辑)/Win(视图) | SQLite schema + Repository + 周视图VM/View；离线可见；重复展开显示 |
| **M3** | 增删改 + 乐观并发 | 3d | M2 | Linux(协议)/Win(窗口) | 快速新增窗口 + PUT/DELETE + `If-Match`；本地优先写；保留 `X-` 属性 |
| **M4** | 同步引擎 | 3d | M3 | Linux | 定时/手动同步 + `sync-token` 增量 + ETag比较 + 冲突提示 + 失败警告 |
| **M5** | 桌面窗口 + 系统集成 | 4d | M2 | Windows | 无边框透明三模式 + Win32样式 + 多显示器/DPI + 托盘 + 开机启动 + 设置 |
| **M6** | 重复事件 + 提醒 | 3d | M2 | Linux(模型)/Win(提醒) | Series/Occurrence/Exception + 简单重复创建 + 删除系列 + EXDATE + 到期通知 |
| **M7** | 打磨与发布 | 2d | M5,M6 | Windows | 单文件 EXE + 性能/错误处理 + 诊断；首发上线 |

**并行机会**：
- M6 的重复模型（Linux，纯逻辑）可与 M5（Windows，窗口）并行推进。
- M4 同步引擎（Linux）可与 M3 的快速新增窗口（Windows）末段重叠。
- 每个里程碑的 Linux 侧单测不阻塞 Windows 视图工作。

## 四、需要你提前确认/拍板的事项（按门禁分组）

> 带「建议默认」的，无异议即按默认推进；其余需你明确。⭐ = 影响数据安全或工程量，务必先定。

### G0 — 开工前（影响 M0 与整体分发）
1. ⭐ **发布形态**：✅ **framework-dependent 单文件（已定）** —— 不打包运行时（你的机子已装 .NET 10 桌面运行时），体积小。命令：`dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true`。
2. **目标 Windows 版本**：Windows 10 (21H2+) / 11（**建议**：10 21H2 及以上）。
3. **UI 语言**：简体中文（确认）。
4. **数据/配置目录**：`%AppData%\CalDesk`（SQLite + 配置）；凭据走 Windows Credential Locker（确认）。
5. **分支策略**：`main` + 每`里程碑/特性` 分支（确认）。

### G1 — M1 连通前
6. **多日历范围**：确认首发覆盖 `work`/`personal`/`holiday` 三日历；`contact`（CardDAV 通讯录）**按 `resourcetype` 过滤掉**（已确认存在，超范围）。
7. **认证**：HTTP Basic（已实测确认）；凭据存 Credential Locker（确认）。
8. **时区 / 地区 / 周首日**：`Asia/Shanghai`、一周从**周一**开始（从你的样例推断，确认）。

### G2 — M2 周视图前
9. **周视图默认范围**：① 本周（周一起，**建议**）② 未来 7 天滚动。
10. ⭐ **「已过去事项」规则**：① 已结束则隐藏 ② 当天结束后隐藏 ③ 仍进行中的高亮（**建议：当天已结束隐藏、进行中高亮、跨天保留**）。
11. **空状态文案**：「暂无事项」（确认）。

### G3 — M3 增删改前
12. **默认值**：默认日历=`work`、默认时长=`1h`、默认提醒=`提前 15 分钟`（确认/调整）。
13. **UID 方案**：`<新GUID>@caldesk`，资源路径 `<uid>.ics`（确认）。
14. **快速新增日历下拉**：支持在 work/personal/holiday 间切换（建议支持）。

### G4 — M4 同步前
15. **同步间隔**：默认 5 分钟、可配；手动刷新入口=托盘 + 周视图刷新按钮（确认）。
16. ⭐ **冲突 UX（关键，影响数据安全）**：本地与远端同时变化时——**建议：保留两份，本地标记「冲突」，托盘+角标提示，由你选择保留哪份；绝不静默 LWW**。需确认提示形式与默认动作。
17. **离线重试**：指数退避、最多 N 次（建议 N=5）后转为失败警告，等你手动处理。

### G5 — M5 桌面窗口前
18. **默认显示器**：记忆上次所在显示器（确认）。
19. **默认窗口模式**：① 普通窗口 ② 桌面模式 ③ 置顶模式——**建议默认「普通窗口」**，稳定后再切桌面/置顶。
20. **默认透明度**：建议 85%。
21. **开机启动**：默认**关**，设置中可开（建议）。
22. ⭐ **WorkerW 桌面嵌入**：MVP **不做**（实验、易随系统更新失效，**强烈建议**移到后续实验功能）。
23. **鼠标穿透（click-through）**：MVP **不做**（确认）。

### G6 — M6 重复+提醒前
24. **重复预设**：每日 / 每周 / 每月（建议先这三项）；是否加「每工作日」「每年」？
25. ⭐ **提醒通道（WPF 注意点）**：Windows Toast。**单文件非打包 EXE 需在开始菜单创建带 AUMID 的快捷方式，Toast 才能进操作中心**；否则退化为托盘气泡。需你确认走 Toast（更原生）还是托盘气泡（更省事，**建议 MVP**）。
26. **远端 VALARM 处理**：你日历里事件自带提醒（`-PT15M`/`-PT1H`）——**建议尊重远端 VALARM**，无则用本地默认提醒（确认）。

### G7 — M7 发布前
27. **代码签名**：有无证书？无则首发不签名（SmartScreen 首次会警告）。
28. **分发方式**：便携 zip（**建议**）还是安装器。
29. **版本号**：从 `0.1.0` 起步（确认）。
30. **错误上报/遥测**：**不做**，仅本地日志（确认）。

## 五、影响排期的关键风险与决策点

| 项 | 风险/影响 | 建议 |
|---|---|---|
| ⭐ 冲突 UX（G4-16） | 默认 LWW 会静默丢数据；做得过重又拖慢 M4 | MVP 保留两份 + 显式提示；不上自动合并 |
| ⭐ WPF Toast（G6-25） | 非打包单文件 Toast 需 AUMID 快捷方式，否则不进操作中心 | MVP 用托盘气泡，Toast 留后续 |
| WorkerW（G5-22） | 非公开技巧，系统更新易失效 | MVP 不做，普通无边框+锁定位置 |
| 浮动时间事件 | 真实数据含无 `Z`/`TZID` 事件，解析错误会错位 | M1 即严格按本地时间解释浮动时间 |
| 发布体积（G0-1） | framework-dependent 单文件，需目标机预装运行时 | 已确认目标机有运行时；安装文档需注明依赖 |
| CardDAV 通讯录 | `/mar/contact/` 会被枚举到 | 按 `resourcetype` 过滤，仅取 `<C:calendar/>` |

## 六、推进规则（每里程碑 Definition of Done）

- 每个里程碑结束须满足其「验收门槛」+ 该里程碑相关单测/集成测试通过。
- **以 radical 三日历真实数据为通过线**：稳定后再扩其它服务器兼容。
- 每动 SQLite schema / CalDAV 请求 / 重复逻辑 → 重跑对应里程碑验收。
- 阶段 A/B 的 Linux 侧测试先行；Windows 视图集成在阶段末突击，减少环境切换。
